# Description

Unrelated but I've been trying to solve some problems with my local crate digging workflow. Specifically, I have lots of duplicates between playlists. That being said the metadata from the playlist is valuable. I used to think of playlists as a first order concept, that evolves and is well defined. But as I've seen with "daytime rave" and "night music", that definition changes over time. That being said, it's still useful. As in, it provides a quick descriptive sense of "snapshot" data, like what I was thinking in that moment in time. Was able to vibe code this wrapper to use `scdl` and `spotdl` more universally and also keep track of duplicates in archive.txt files instead.
